# Архитектура 3D-сцены

Дополнительный артефакт направления B. Описывает, как устроена сцена тура, откуда берётся контент и как точка интереса связана с процессом и метрикой.
Код лежит в `frontend/src/3d/scene/`.

## Технология

- **WebGL 2 через Three.js 0.169.** Задание требует браузер, WebGL или Three.js, без Unity, Unreal и плагинов (НФТ-2).
- **react-three-fiber 8.** Сцена описывается React-компонентами, а состояние тура общее с остальным интерфейсом.
- **drei 9:**
  - `OrbitControls` — камера;
  - `Html` — метки точек как HTML поверх 3D;
  - `useGLTF` — загрузка `.glb` с Draco;
  - `Instances` — массовые объекты;
  - `PerformanceMonitor` — снижение качества на слабых устройствах.
- **Zustand.** Хранит состояние тура: маршрут, шаг, локацию, выбранную точку, режим редактора.

## Три уровня сцены

```
Генплан (overview)  →  Локация (model | panorama)  →  Точка интереса  →  Этап процесса → Метрика / Кейс
```

| Уровень | Компонент | Что видно | Как перейти дальше |
|---|---|---|---|
| Генплан | `SiteOverview.jsx` | территория, здания цехов, дороги, ж/д, АБК, парковка; здания маршрута подсвечены; над цехами — загрузка этапа в %; поток партий по этапам с очередью перед узким местом и красный маяк над ним | клик по зданию или мини-карта |
| Локация — 3D-модель | `ModelScene.jsx` | цех из `.glb` (asset_url) или процедурная модель: движущийся конвейер, погрузчик, мешалки, поток масла в трубах, табло этапа с длительностью и загрузкой | клик по метке или по списку точек |
| Локация — панорама 360° | `PanoramaScene.jsx` | сфера с панорамой, камера в центре. Файл заказчика (`.jpg`) или комната, собранная кодом (`LabRoom.jsx`) и снятая кубической камерой один раз | клик по метке |
| Точка интереса | `Hotspot.jsx`, `PointList.jsx` | метка-кнопка ≥ 44 px, номер шага маршрута, подпись; в 3D-модели — «ножка» до пола с кольцом; рядом — список точек локации | карточка → «Процесс», «Кейс», «Открыть в дашборде» |

Обратный путь — от метрики к сцене. Экраны процесса, кейса и дашборда имеют кнопку «Показать в туре». Она открывает локацию этапа через `goToLocation(location_id, hotspot_id)`.

Цифры на сцене (загрузка, длительность, узкое место) считает `store/stats.js` из последних значений метрик. Если тур получил расчёт цифрового двойника (`api/twin.js`), берутся его цифры — см. `README.md`, раздел «Данные из цифрового двойника».

## Всё, что видно на сцене, описано в данных

| Что | Где хранится | Поле |
|---|---|---|
| Тип сцены локации | `locations` | `scene_type`: overview, model, panorama |
| Файл сцены | `locations` | `asset_url`: путь к `.glb` или `.jpg`; `procedural:<код>` — сцена собирается кодом (1 этап) |
| Место здания на генплане и на мини-карте | `locations` | `map_x`, `map_y` (0–100) |
| Положение метки в 3D | `hotspots` | `pos_x`, `pos_y`, `pos_z` |
| Положение метки в панораме | `hotspots` | `yaw`, `pitch` |
| Видимость метки | `hotspots` | `status` (в туре показываются только `published`) |
| Связь с процессом | `hotspots` | `stage_id` → `process_stages` → `metrics` |
| Связь с кейсом | `hotspots` | `case_id` → `cases` → `metrics` |
| Шаги маршрута и текст гида | `route_steps` | `location_id`, `hotspot_id`, `narration` |

Другое предприятие означает другой набор данных. Код при этом не меняется (НФТ-7).
На 2 этапе процедурные сцены заменяются файлами заказчика: в `asset_url` записывается путь к `.glb` или панораме.

## Компоненты

```
<TourCanvas>                       холст, свет, переключение сцены, затемнение, мини-карта
  <Canvas>
    <PerformanceMonitor/>          dpr 2 → 1 при просадке кадров
    <Atmosphere/>                  небо-градиент, туман, солнце (тени только на ПК),
                                   окружение из Lightformer'ов для отражений (без скачивания HDR);
                                   на телефоне — одна статичная контактная тень
    <EditorPicker>                 в режиме редактора ловит клик по геометрии
      <SiteOverview | ModelScene | PanoramaScene/>
    </EditorPicker>
    <Hotspot/> × N                 HTML-метки поверх 3D
    <CameraRig/>                   OrbitControls, ракурсы, подлёт к точке
  </Canvas>
  <PointList/>  <MiniMap/>  <EditorForm/>  <TourTextVersion/>   (без WebGL — только текстовая версия)
```

## Камера

| Сцена | Управление | Ограничения |
|---|---|---|
| Генплан | вращение и приближение вокруг территории | наклон 9°–79°, дистанция 18–95 м |
| 3D-модель цеха | вращение, приближение, сдвиг | камера не уходит под пол, дистанция под размер цеха (`VIEWS` в `sceneUtils.js`) |
| Панорама | поворот из центра, приближение колесом или щипком (угол обзора 35°–90°) | без сдвига |

Камера ведёт себя так:
- при входе в локацию — короткий облёт к стартовому ракурсу (переход скрыт затемнением);
- при выборе точки в цехе она плавно поворачивается к метке и приближается к ней; на генплане — показывает завод общим планом со сдвигом к точке;
- в свободном осмотре генплан медленно вращается, пока посетитель ничего не выбрал;
- если пользователь начинает вращать сам, автоперелёт останавливается;
- при `prefers-reduced-motion` камера переходит сразу, без анимации; поток партий, конвейер и погрузчик стоят.

## Переходы и загрузка

- Переход между локациями проходит через затемнение 300 мс без перезагрузки страницы. Сцена открывается, только когда данные локации пришли.
- В памяти одна текущая локация. Следующая локация маршрута подгружается заранее (`useGLTF.preload`).
- Бюджет локации: до 40 тыс. треугольников, модель до 5 МБ (`.glb` + Draco), панорама до 2 МБ для телефона (НФТ-4). Процедурные цеха 1 этапа укладываются в бюджет с большим запасом. Массовые объекты (канистры, бочки, паллеты) рисуются через instancing.

## Телефон и доступность

Телефон:
- `dpr` до 1,5, без теней и сглаживания;
- процедурная панорама: грань куба 512 px вместо 1024 px (≈ 2048×1024 вместо 4096×2048);
- лента точек локации над сценой, мини-карта в правом верхнем углу;
- метки не меньше 44 px, подпись видна только у выбранной метки;
- карточка точки выезжает снизу, мини-карта уменьшается.

Доступность:
- метки — это кнопки: Tab переводит фокус, Enter открывает карточку, Esc закрывает;
- кнопка «Текст» показывает текстовую версию тура: все локации и точки с описаниями без 3D. Она работает и на слабых устройствах.

## Режим редактора (ФТ-12)

1. Кнопка «Редактор» или адрес `/tour?edit=1`.
2. Клик по любому объекту сцены даёт координаты:
   - в 3D — точка попадания плюс 0,8 м вверх;
   - в панораме — yaw и pitch направления.
3. Форма: название, описание, привязка к этапу и кейсу. Тип точки выбирается автоматически.
4. Сохранение:
   - в режиме `mock` — в localStorage браузера;
   - в режиме `live` — `POST /api/hotspots/`.

   Точка сразу появляется в туре, правка кода не нужна.

## Связь с бэкендом

`frontend/src/3d/api/client.js` работает в двух режимах:
- `VITE_API_MODE=mock` — данные из `src/3d/api/mock`;
- `VITE_API_MODE=live` — запросы к Django REST API по контракту из документа «Структура проекта».

Сцене нужны запросы:
- `GET /api/locations/` — список локаций для генплана и мини-карты. **Этого запроса нет в таблице API документа, его нужно добавить бэкенду**;
- `GET /api/locations/{id}/` — локация с опубликованными точками;
- `GET /api/hotspots/{id}/` — точка с медиа, этапом, кейсом и последними значениями метрик этапа;
- `GET /api/routes/{id}/` — маршрут с шагами;
- `GET /api/processes/{id}/` — нужен, чтобы определить узкое место по максимальной загрузке;
- `POST /api/hotspots/`, `PATCH /api/hotspots/{id}/` — редактор;
- `POST /api/events/` — анонимные события `open` и `finish` для статистики.
