# Эксплуатация и границы

## Перед размещением на сервере

1. Установить DJANGO_DEBUG=false и случайный DJANGO_SECRET_KEY длиной не менее 50 символов.
2. Настроить HTTPS на внешнем reverse proxy, точные ALLOWED_HOSTS, CORS_ALLOWED_ORIGINS,
   CSRF_TRUSTED_ORIGINS и secure cookies. Compose по умолчанию публикует порт только на loopback.
3. Не публиковать порт PostgreSQL. Хранить .env вне Git, менять учебные пароли.
4. Отключить SEED_DEMO и удалить учебные аккаунты/контент перед реальной загрузкой.
5. При необходимости доверия X-Forwarded-Proto включать TRUST_PROXY только за прокси,
   который сам перезаписывает заголовок. Встроенный nginx передаёт $scheme;
   если TLS завершается выше, согласовать цепочку прокси отдельно.
6. После HTTPS задать SECURE_SSL_REDIRECT=true и осмысленный SECURE_HSTS_SECONDS.
   Эти переменные для production нужно дополнительно передать сервису backend в Compose.
7. `python manage.py check --deploy` и smoke test на реальном домене.

Docker здесь содержит конфигурацию для локального демо. Установка TLS, домена,
резервного копирования и инфраструктуры команды не выполнялась.
Swagger UI загружает ресурсы CDN по умолчанию; в офлайн-среде используйте сохранённый
openapi.yaml или отдельно разместите Swagger UI assets.

## Данные и безопасность

Роль задаётся на сервере, пользователь не может назначить её себе при регистрации.
Пароли хэшируются Django; refresh-токены ротируются с blacklist.
Админка защищена CSRF. API использует заголовок Bearer, CORS — явный список.
Глобальные роли открывают контент всех предприятий; это не multi-tenant сервис.
Файлы в media предназначены для публичного тура, не для документов ограниченного доступа.
Загрузка проверяет размер, расширение и сигнатуру; антивирус не включён.
Удаление записи media не удаляет физический файл автоматически: отдельная уборка
нужна после проверки, что файл больше нигде не используется.

Встроенный DRF throttling использует локальный cache процесса: это базовая защита прототипа,
а не распределённый лимитер. Для публичного запуска добавьте Redis cache или лимиты на proxy.
Не включайте логирование JWT, паролей, тел регистрации и UUID сессий.
Nginx access log выключен; при включении определите срок хранения и состав полей.

## Минимизация персональных данных

Регистрация: username, email, хэш пароля, consent_at и policy_version.
Не запрашиваются ФИО, телефон и другие данные. DELETE auth/me/ удаляет аккаунт.
Анонимные события не ссылаются на пользователя, не содержат IP и email;
UUID следует менять при новом прохождении и не связывать с учётной записью.
Эндпоинт удаления не очищает внешние backups/логи — установите сроки их хранения.

Перед работой с реальными посетителями заказчик должен предоставить текст политики,
реквизиты оператора, правила согласия, хранения, удаления и размещения данных.
Версию POLICY_VERSION в accounts/serializers.py необходимо согласовать с опубликованным текстом.
Фронтенд обязан показывать политику перед согласием. Этот комплект не удостоверяет
юридическое соответствие требованиям законодательства.

Периодическая уборка:

```bash
python manage.py purge_events --days 90
python manage.py flushexpiredtokens
```

Настройте выполнение раз в сутки штатным планировщиком сервера.

## Резервное копирование

```bash
docker compose exec -T db pg_dump -U plant_tour plant_tour > backup.sql
```

Команда использует значения имени БД и пользователя из примера; замените при необходимости.
Отдельно копируйте media_data; храните backups вне сервера приложения.
Проверяйте восстановление в тестовую БД. Не публикуйте backup.sql в Git.

## Ограничения направления B

- Нет расчёта производственных сценариев/SimPy и сравнения симуляций: они относятся к A.
- В дашборде показываются сохранённые наблюдения, кейсы — заданные значения до/после.
- Нет ERP/MES/1C и автоматической синхронизации.
- Нет frontend, геометрии, панорам, UI согласия и 3D-редактора; серверные API для них готовы.
- JSON импорт поддерживает контент, CSV — историю метрик, без произвольного маппинга колонок.
- Демо не предназначено для больших каталогов без профилирования и оптимизации запросов.
- Есть 14 доменных моделей плюс служебные таблицы Django и blacklist.
